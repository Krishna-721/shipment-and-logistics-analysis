# Safiri PortPulse — Assumptions

## 1. Data Assumptions

* The project uses **synthetic port-operation data** rather than live AIS or port data.
* Each record represents the operational state of a port at a specific point in time.
* Multiple synthetic ports are used to introduce differences in capacity, traffic, and operational behavior.
* The generated data is designed to represent realistic relationships rather than independent random variables.
* A fixed random seed is used to make the dataset reproducible.
* Some randomness and noise are intentionally introduced to avoid perfectly deterministic relationships.

## 2. Operational Assumptions

* Vessel arrivals create demand on port resources.
* Limited berth and service capacity can cause queues to grow.
* Weather, equipment availability, and labor availability can reduce effective service capacity.
* Higher queues and waiting times generally increase shipment delay.
* Port conditions vary over time due to daily and seasonal patterns.
* Historical port performance provides useful context for current risk.

## 3. Prediction Assumptions

* The system predicts **congestion risk over the next 6 hours**.
* Predictions use only information available at the prediction timestamp.
* Future operational outcomes are not used as input features.
* Congestion is treated as a binary operational state for the primary classification task.
* Expected delay is treated as a separate regression target.
* Model probabilities are interpreted as risk estimates rather than guaranteed outcomes.

## 4. Modeling Assumptions

* Logistic Regression provides the baseline model.
* Tree-based models such as Random Forest and XGBoost may be evaluated as stronger options.
* The final model will be selected based on predictive performance, calibration, interpretability, and complexity.
* The dataset is sufficiently representative for demonstrating the approach, but not for claiming real-world production accuracy.
* SHAP explanations are used to identify the main factors influencing individual predictions.

## 5. Recommendation Assumptions

* Recommendations are generated by a deterministic rule-based layer.
* Recommendations are based on predicted risk, expected delay, and relevant operational indicators.
* The system provides **decision support**, not autonomous operational decisions.
* A human operator remains responsible for the final decision.

## 6. Evaluation Assumptions

* Classification performance is evaluated using Precision, Recall, F1-score, ROC-AUC, PR-AUC, and Brier Score.
* Delay prediction is evaluated using MAE, RMSE, and R².
* Time-aware evaluation is preferred where appropriate to better represent future prediction.
* Performance on synthetic data does not imply equivalent performance on real port data.

## 7. Scope Assumptions

This project is a **3-day proof-of-concept**.

The system does not attempt to provide:

* Live AIS ingestion
* Real-time weather feeds
* Production-scale streaming
* Route optimization
* Autonomous decision-making
* Full port-management software
* Guaranteed real-world predictions
